# API and server-action reference

Current local implementation, 17 September 2026. This is a first-party Next.js application, without a supported public REST CRUD API. Browser forms call imported server actions; their internal transport is not a stable integration contract. Frontend and backend run in the same Next.js process.

## HTTP routes

| Route | Method | Access and input | Success | Failure |
|---|---|---|---|---|
| `/api/health` | GET | Public; core environment and database check | 200 `{"status":"ok"}` | 503 `{"status":"unavailable"}` |
| `/api/upload` | POST | Multipart `jobId`, `email`, six-digit `otp`, `file`; live challenge, open job and eligible plan | 200 `{"uploadId":"UUID"}` | 400 invalid form/type/job, 403 challenge/plan, 413 declared request too large, 429 IP allowance, 500 processing failure |
| `/api/resumes/[id]` | GET | Signed-in hiring role; candidate ID in active workspace | 307 short-lived download redirect; private/no-store | 403 unauthorized, 404 absent, 503 storage failure |
| `/api/application-resumes/[id]` | GET | Signed-in hiring role; application ID in active workspace | 307 application snapshot download redirect | 403, 404, 503 |
| `/api/auth/[...nextauth]` | GET/POST | Auth.js session, credentials and CSRF protocol | Auth.js responses/cookies | Auth.js error responses; use its client helpers |
| `/api/auth/verify-email` | GET | `email`, `token`; matching unexpired single-use verification record | Redirect `/login?verified=1` | Redirect with `verify_error=missing_params`, `invalid_token` or `server_error` |
| `/api/auth/google-calendar/connect` | GET | Workspace owner/admin; configured Google OAuth | Google authorization redirect | Configuration/authentication errors or sign-in redirect |
| `/api/auth/google-calendar/callback` | GET | `code`, `state`; matching OAuth state cookie and authorized workspace | Team-page redirect | Team-page error redirect; no provider body exposed |
| `/api/billing/webhook` | POST | Raw JSON; `stripe-signature`; configured secret | 200 `{"received":true}`; duplicates safe | 400 bad signature/body, 503 unavailable configuration, 500 retryable handling error |
| `/api/cron/interview-reminders` | GET | `Authorization: Bearer CRON_SECRET` | Counts `checked`, `sent` (delivery intents queued) | 401 or 500 |
| `/api/cron/email-outbox` | GET | Cron bearer secret | Counts `checked`, `sent`, `failed` | 401; unexpected database failure is a server error |
| `/api/cron/resume-cleanup` | GET | Cron bearer secret | Cleanup counts | 401 or 500 |
| `/api/cron/ai-scoring` | GET | Cron bearer secret | `enabled`, `checked`, `completed`; one AI job per batch | 401 or 503 |

Resume downloads depend on Cloudinary configuration and storage records. Legacy public assets remain public at the provider until migrated. An upload ID is a temporary claim, not an application or a public resume URL. It expires after 30 minutes and is consumed by application creation. Files are PDF/DOCX only, nonempty and at most 3 MiB. DOCX archives are also checked for bounded expansion, unsafe paths and XML entity declarations.

Examples using placeholder values:

```sh
curl http://localhost:3000/api/health
curl -X POST http://localhost:3000/api/upload \
  -F 'jobId=EXISTING_JOB_ID' -F 'email=applicant@example.test' \
  -F 'otp=CODE_FROM_EMAIL' -F 'file=@resume.pdf;type=application/pdf'
```

Use a real challenge generated by the application, never a guessed code. Do not put cron credentials in URLs, screenshots or committed command files. Billing webhook tests must sign the exact raw body; a checkout redirect never grants a plan.

## Server-action contracts

| Module | Operations | Authorization and validation |
|---|---|---|
| `actions/auth.ts` | register, login, resend verification, request/reset password | Normalized emails, shared counters, verified credentials; new passwords 8+ characters, uppercase, digit, symbol, at most 72 UTF-8 bytes; login permits existing 6+ character passwords within 72 bytes |
| `actions/public-apply.ts` | send/verify OTP, submit, application status | No candidate account; one email challenge across entry points; five incorrect guesses lock it; submission atomically consumes OTP/upload and records privacy acknowledgement |
| `actions/create-job.ts`, `jobs-pool.ts` | job creation/list/status/delete | Workspace hiring roles, runtime validation and serialized active-job capacity checks |
| `actions/application.ts` | applicants, change stage, queue AI review | Workspace hiring roles; allowed stages; applicant pages of 100; stage change, audit and notification intent in one transaction |
| `actions/interview.ts`, `interviews-pool.ts` | schedule/list/feedback/rate/cancel/request experience | Workspace authorization; interviewer lists restricted to own assigned interviews in active organization, private candidate/reviewer ratings masked; 15–480 minute durations, valid timezone/future date; overlapping scheduling serialized within organization; single-use experience link |
| `actions/team.ts`, `workspaces.ts` | invites/accept/removal/bio/calendar disconnect/switch | Owners/admins manage teams; owner protections; invitation email identity; seat reservations; switch requires membership |
| `actions/agency-clients.ts` | create/list/assign clients | Hiring roles; tenant-scoped job/client relationship; max 500 clients per workspace |
| `actions/candidates-pool.ts` | list/search/export | Hiring roles; workspace scope; escaped CSV formulas; authorized resume routes replace raw stored URLs |
| `actions/billing.ts` | checkout/portal | Owner only; server price/currency validation, idempotency and canonical subscription state |

Actions generally return `{success: "message"}` or `{error: "safe message"}`. Lists return data and pagination flags; form actions may redirect instead. These are application results, not separate HTTP status codes. Unauthorized operations must fail on the server regardless of hidden UI buttons. Provider scoring is optional: intake commits first and records durable work; scores never automatically hire/reject an applicant. Pending/failed work can be retried through the authorized review action.

No permissive credentialed CORS API is configured. Auth.js and Next.js server-action origin/CSRF checks protect their own protocols; those protections do not make the intentionally public applicant upload an authenticated recruiter endpoint.
